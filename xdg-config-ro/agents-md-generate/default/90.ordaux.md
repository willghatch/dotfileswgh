# Ordaux

`ordaux` introduces task-specific overrides of the defaults in this AGENTS.md.
It allows the user to write shorthands for workflow variants.
Read its control sentence through the first newline or sentence-ending punctuation.
Recognize the shorthands below anywhere in that sentence, and interpret the remaining words as ordinary instructions.
Shorthands on different axes combine.

| Shorthand | Behavior |
| --- | --- |
| `wt` | Use a temporary worktree, including for work that would otherwise be exempt. |
| `main-wt` | Work in the main worktree on its current branch. |
| `branch:NAME` | Create or continue on branch `NAME`. |
| `new-branch` | Create a new branch using the default naming rules. |
| `no-commit` | Leave this task's changes uncommitted. |
| `one-commit` | Make one commit for the task when the work is finished. |
| `keep-wt` | Leave the temporary worktree in place when finished. |
| `manager` | Disclose `manager` and manage subagents for the task. |
| `solo` | Do not use subagents. |
| `focused-test` | Run tests focused on the changed behavior. |
| `full-test` | Run the full applicable test suite. |
| `read-only`/`ro` | Inspect and advise without editing files. |
| `plan-only` | Produce a plan without implementing it. |
| `submodules`/`submod` | Allow editing submodules. |
| `no submod` | Disallow editing submodules. |
| `caveman` | Why say lot word, few do trick. |
| `web`/`www` | Consult the web. |
| `mem`/`memory` | Don't consult sources, just work from memory. |
| `bench`/`no-bench` | Require or skip performance measurements. |
| `subagent-review` | Have a subagent review your work critically, and edit based on it. |
| `review to pass` | Loop on subagent review until passing. |

When `branch:NAME` selects a branch already checked out in a worktree, use that worktree.
Be flexible about dashes vs spaces, comma separated vs not, etc in interpreting ordaux -- it is a shorthand.
Both `yes` and `no` are prefixes by default: "yes wanted", "no unwanted" -- positive and negative versions of anything can be used.
Some of them have no explicit default behavior, while others are mostly about overriding user-level or project-level defaults.
The table is not exhaustive, try to be reasonable based on that table when interpreting other ordaux commands.

## Examples

- `ordaux no-commit main-wt.` - work in main worktree without committing, useful for interactive experiments.
- `ordaux just chat, no-submod no tdd yes format no web.` - communicate via chat instead of report files, don't edit submodules, don't use tdd, but do format, and don't use www resources.
- `ordaux review 3x per commit` - use subagent review up to 3 times or until passing before each commit.

## Other misc defaults

By default, editing submodules is allowed with parley sign-off but not otherwise.
